# 03 营养数据与代谢配置

本章定下代谢系统（[02](02-metabolism.md)）所用的每份成分数据从哪里来、怎样经数据包配置，以及代谢系统的配置项。方向于 2026-11-13 定下（[11](../additives/11-roadmap.md) 问题 46）：死亡是否清空由配置文件决定；营养数据按食品设定、实际成分、加工工艺逐个确定，经数据包配置，另备 AI 执行的配置流程；慢性部分由配置文件开关，默认开启。第 5 节的细节同日续定。

## 1 数据从哪里来

| 食物 | 每份成分的来源 |
| --- | --- |
| 本模组成品 | 算法从配方算出（[01](01-overview.md) 第 4 节），由数据生成写出，随模组发布 |
| 原版食物 | 按第 4 节的流程逐个配置，配置结果作为数据生成的输入，由数据生成写出，随模组发布 |
| 农夫乐事 | 同原版（本模组已联动农夫乐事，11 问题 14）；26.1.2 节点暂无农夫乐事，该节点不生成农夫乐事的数据（[I34](../implementations/I34-nutrition-data.md)） |
| 其他模组 | 整合包作者或玩家按第 4 节的流程配置，放进自己的数据包；交给 AI 执行时用 [agents/food-nutrition-data.md](agents/food-nutrition-data.md) |

- **本模组附带的数据全部由数据生成写出**（2026-11-13 定）：本模组的 `foodindustrial/nutrition/*.json` 一律由数据生成写出，包括本模组成品，以及原版、农夫乐事等随模组附带的他方食物；生成的文件不手改。原版、农夫乐事等手工配置的数值与 `basis` 是数据生成的输入，放在仓库哪里由实装定（2026-11-13 用户定，记在 [I34](../implementations/I34-nutrition-data.md) 的实现记录）。数据生成时检查六个成分键齐全、手工配置的条目带 `basis`（2026-11-13 确认）。
- 依据（已定）：食品设定（名称、描述、配方、加工方式）、实际成分（现实中对应食物的成分数据）、加工工艺（烹调、发酵等带来的变化）。不按物品标签给类别默认值（02 第 8 节原建议不采用）。
- 数据包只决定代谢系统的成分，不改任何物品的饱食度、饱和度；他模组食物的饱食度、饱和度仍由该模组决定。
- 没有数据的食物：吃下后不计入任何成分（不带咖啡因、酒精、快吸收糖，也不补营养素），不报错；第 3.2 节的命令列出这些食物。
- 杂质：本模组成品按“土法”“劣质”标签计（01 第 5 节）；原版与他模组食物在设定中“不健康”的（如腐肉、蜘蛛眼），由数据的可选字段 `impurity` 给出每份杂质，经用户决定（2026-11-13 用户要求）。两者同时存在时相加。

## 2 数据包格式

位置：`data/<命名空间>/foodindustrial/nutrition/<名称>.json`，与外部纯度规则（[10](../additives/10-purity-jei-ae2.md) 第 1.6 节）同一目录约定。服务器启动与 `/reload` 时加载，并同步到客户端，Tooltip 与“体内”面板的显示与服务端一致。

示例（尖括号为占位，实际写数值）：

```json
{
  "mod": "othermod",
  "entries": [
    {
      "items": ["othermod:iced_coffee"],
      "serving_g": "<一份的克数>",
      "per_serving": {
        "caffeine_mg": "<每份咖啡因>",
        "alcohol_g": 0,
        "fast_sugar_g": "<每份快吸收糖>",
        "vitamin_c_mg": "<每份维生素 C>",
        "vitamin_b1_mg": "<每份维生素 B1>",
        "vitamin_d_ug": "<每份维生素 D>"
      },
      "impurity": "<每份杂质单位，可省略>",
      "energy_kcal": "<每份能量>",
      "basis": {
        "food": "<对应的现实食物>",
        "sources": ["<资料名与页码、表号或网址、条目编号>"],
        "processing": "<加工方式与所用保留率>",
        "assumptions": ["<经用户确认的假设>"],
        "confirmed": "<确认日期>"
      }
    }
  ]
}
```

| 字段 | 说明 |
| --- | --- |
| `mod` | 必填。数据针对的模组 ID；该模组未加载时整份跳过，不记警告 |
| `priority` | 可省略，默认 0。同一物品出现在多份文件时取数值大的一份；相同时记警告，取文件 ID 按字典序靠后的一份 |
| `entries[].items` | 必填。物品 ID 列表，同一条目的物品共用数据；不接受标签。不存在的 ID 记警告后忽略 |
| `entries[].serving_g` | 必填。一份（吃或喝一次）的可食部克数；饮料按体积乘密度折算 |
| `entries[].per_serving` | 必填。每份所含成分，键见下表。缺省的键按 0 计；手工配置时六个键全部写出，0 也写出 |
| `entries[].impurity` | 可省略，默认 0。每份带入的杂质单位（02 第 5.1 节），不是成分键，不计缺键；只给设定中“不健康”的食物，数值由用户决定（2026-11-13） |
| `entries[].energy_kcal` | 可省略。每份能量，只进报表，与该食物原有的饱食度对照，不影响游戏 |
| `entries[].basis` | 手工配置的条目必填，游戏不读取。`food` 对应的现实食物；`sources` 数据来源；`processing` 加工方式与所用保留率；`assumptions` 经用户确认的假设（一份的重量、配料比例等）；`confirmed` 确认日期 |

| 键 | 成分 | 单位 | 计法 |
| --- | --- | --- | --- |
| `caffeine_mg` | 咖啡因 | mg | 02 第 4.1 节 |
| `alcohol_g` | 酒精 | g | 酒精度 × 体积（mL）× 0.789 g/mL（02 第 4.2 节） |
| `fast_sugar_g` | 快吸收糖 | g | 02 第 4.3 节，按 WHO 的游离糖计（第 5 节第 1 条） |
| `vitamin_c_mg` | 维生素 C | mg | 02 第 5.3 节 |
| `vitamin_b1_mg` | 维生素 B1 | mg | 02 第 5.4 节 |
| `vitamin_d_ug` | 维生素 D | µg | 02 第 5.5 节 |

- 以后加入的成分（02 第 6 节）增加新键；旧文件缺少新键时按 0 计，并在第 3.2 节的清单里标为“缺键”，提醒补配。
- 触发：吃或喝的使用动作完成时按物品 ID 查数据（使用动画为进食或饮用），没有原版食物属性的饮品（牛奶桶、他模组的饮料）同样按数据计入。
- 放置后分口吃的方块食物（原版蛋糕等）以一口为一份，`items` 写该方块的物品 ID，触发方式由实装方处理。
- 本模组附带的数据由数据生成写出（第 1 节）；整合包要改时另写 `priority` 大于 0 的文件覆盖。
- 格式错误的文件记错误后整份跳过（同 10 第 1.6 节）。

## 3 配置项与命令

### 3.1 配置项

`config/foodindustrial-common.toml` 的 `[metabolism]` 节，键名照现有配置项的写法：

| 键 | 默认 | 作用 |
| --- | --- | --- |
| `clear_on_death` | `true` | 死亡后清空体内量（咖啡因、酒精、快吸收糖、杂质），营养素储备回到上限；`false` 时死亡前后全部保持 |
| `impurity` | `true` | 杂质（02 第 5.1 节）。关闭时不计入、不显示，已有效果移除，体内量归零 |
| `nutrients` | `true` | 营养素（02 第 5.2–5.5 节）。关闭时不计入、不消耗、不显示，已有效果移除，储备回到上限 |
| `unconscious_screen` | `true` | 失去意识时画面变黑（02 第 4.2 节） |
| `unconscious_movement` | `true` | 失去意识时不能移动、跳跃 |
| `unconscious_attack` | `true` | 失去意识时不能攻击 |
| `unconscious_blocks` | `true` | 失去意识时不能破坏、放置方块 |
| `unconscious_use_items` | `true` | 失去意识时不能使用物品 |
| `unconscious_containers` | `true` | 失去意识时不能打开容器 |
| `unconscious_wake_on_damage` | `false` | 失去意识时受到伤害即醒来 |

- 已定（问题 46）：死亡是否清空由配置决定；慢性部分设开关，默认开启。
- 已定（2026-11-13，第 5 节第 5 条）：死亡的默认值取清空（沿用 02 第 8 节原建议）；杂质与营养素分成两个开关；关闭后重新开启从初始状态开始（杂质 0、储备满），不补算关闭期间的变化。
- 已定（2026-11-13，问题 47）：失去意识的各项效果由配置逐项开关，默认全部生效、受伤不醒；七个键名照现有写法拟定。
- 急性部分（咖啡因、酒精、快吸收糖）不设整体开关，问题 46 只涉及慢性部分。
- 多人游戏以服务端的配置为准；客户端只显示服务端同步来的状态。

### 3.2 命令（权限等级 2）

| 命令 | 作用 |
| --- | --- |
| `/foodindustrial nutrition show <物品>` | 显示该物品生效的数据与所在文件 |
| `/foodindustrial nutrition missing` | 统计已加载的所有可吃、可喝物品中没有数据或缺键的，按模组分组，并导出到游戏目录的 `foodindustrial/nutrition_missing.json`（物品 ID、翻译键、饱食度、饱和度、使用动画、所属模组），作为第 4 节流程的输入。放置后分口吃的方块（蛋糕、农夫乐事的派）一并列出，使用动画写 `bites`，数据按一口计；投掷的药水、26.1 带食物组件却不能吃的鱼桶不列（2026-11-13，I36 前修正） |

数据生成的报表（01 第 4.3 节）同时列出随模组附带的原版、农夫乐事食物的数据，与它们原有的饱食度对照。

## 4 配置流程

流程的完整版本写在 [agents/food-nutrition-data.md](agents/food-nutrition-data.md)，人工配置与交给 AI 配置都照它执行。在 Claude Code 中作为子代理使用时，把该文件末尾“附 Claude Code 子代理入口”的内容存为仓库根目录的 `.claude/agents/food-nutrition-data.md`（远程工具不能写 `.claude` 目录，入口文件由用户建立）。要点：

1. **确定范围**：模组与版本、物品清单（第 3.2 节导出）、资料（模组的语言文件、配方、百科）、输出位置。
2. **弄清食品设定**：名称、描述、配方、加工方式、一次产出几份；不凭物品 ID 单方面认定是什么食物。
3. **对应现实食物**：成分表里有整份条目的直接对应；没有的按配料计算；幻想食物由用户决定对应哪种现实食物或全部按 0。
4. **一份的重量**：取设定写明的，或有出处的现实份量并经用户确认；都没有时询问。不由饱食度倒推（换算曲线未定，01 第 11 节第 7 条）。
5. **取成分**：按第 5 节第 2 条的来源顺序取每 100 g 可食部含量；按配料计算时用 EuroFIR 的配方计算法：各配料按可食部生重加总，按加工得率折算到成品重量，维生素在配料一级乘保留率。
6. **加工变化**：维生素 C、B1 与加酒烹调的菜肴中的酒精按 USDA 营养素保留率表（Release 6）计；该表没有的加工方式询问用户；维生素 D 按不损失计并标出（第 5 节第 3 条）。
7. **核对与写出**：总表经用户确认后写文件，`basis` 写全。随本模组发布的数据写进数据生成的输入，不直接写 `nutrition/*.json`（第 1 节）。

不臆测（流程文件第 0 节）：每个数值都来自本次实际读到的资料并记出处，不用记忆中的数值；对应关系、一份的重量、配料比例、酒精度等没有资料的一律询问；缺数据的成分不默认为 0；用户没有明确同意的建议不写入；作为子代理不能提问时停止，不写数据，返回问题清单。

## 5 细节（2026-11-13 已定）

| # | 问题 | 结论 |
| --- | --- | --- |
| 1 | 快吸收糖的计入范围 | **已定**：按 WHO 的“游离糖”：生产者、厨师或消费者添加的单糖与双糖，以及蜂蜜、糖浆、果汁和浓缩果汁中天然存在的糖；完整果蔬与乳中天然的糖不计。02 第 4.3 节已改；本模组的葡萄汁、柑橘汁带快吸收糖 |
| 2 | 数据来源的顺序 | **已定**：《中国食物成分表 标准版》第 6 版 → USDA FoodData Central → 产品标签与厂商公开数据，每个数值记来源；成分表是纸质书，只取用户提供的书页或用户指定的官方平台上的数值 |
| 3 | 加工变化的算法 | **已定**：本模组算法与手工配置都按 USDA 保留率表（Release 6）计维生素 C、B1 的损失（01 第 4.2 节）；该表没有维生素 D，找到可靠数据前按不损失计，并在 `basis` 与报表中标出 |
| 4 | 农夫乐事的数据 | **已定**：随模组附带，由数据生成写出 |
| 5 | 数据包格式、命令与配置项的细节 | **已定**：按第 2、3 节实装；本模组的 `foodindustrial/nutrition/*.json` 全部由数据生成写出，农夫乐事等随模组附带的他方食物同样由数据生成写出（第 1 节） |
